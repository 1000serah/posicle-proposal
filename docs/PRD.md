# Posicle Proposal — PRD (Product Requirements Document)

## 1. 앱 개요

| 항목 | 내용 |
|------|------|
| 앱 이름 | Posicle Proposal |
| 회사 | 포지클 |
| 목적 | 해외 바이어 대상 K-브랜드/제품 견적 제안 및 발송 이력 관리 |
| 사용자 | 포지클 내부 직원 (1~5명) |
| 접근 방식 | 내부용 웹앱, 반드시 로그인 필요 |

---

## 2. 핵심 문제

1. **발송 이력 관리 부재** — 어떤 바이어에게 어떤 브랜드/제품/자료를 언제 보냈는지 추적이 안 됨
2. **견적 가공 병목** — 공급사 가격표 → 바이어용 견적서 변환에 2~4시간 소요
3. **중복 제안 발생** — 같은 바이어에게 같은 브랜드를 반복 제안하는 실수

---

## 3. MVP 범위

### 포함 (MVP)
- 로그인 (Supabase Auth, 이메일 기반)
- 브랜드/공급사 관리
- 제품 관리 (수동 입력)
- 바이어 관리
- 견적 내역 생성 및 저장 (단가 중심, 화면 내 확인)
- 발송 기록 저장
- 바이어별 / 브랜드별 / 제품별 히스토리
- 후속 연락(follow-up) 일정 관리
- 자료 링크 저장 (URL + 메타데이터 기반)
- 대시보드 (주요 통계 + 오늘 할 일)

### 제외 (2차 개발)
- 사용자별 세밀한 권한 관리 (RLS, buyer_access)
- Excel / PDF / JPG 파일 자동 파싱 (OCR)
- 바이어용 견적서 PDF/Excel 자동 생성
- Gmail 자동 발송
- Google Drive API 연동
- AI 제안서 자동 생성
- 공급사 가격표 버전 관리
- 환율 자동 연동
- 바이어 담당자 다중 관리 (buyer_contacts)
- 판매가 기준 마진 계산 방식 (B방식)
- 견적 비용 항목 세분화 (proposal_cost_items)
- PO/주문 관리 (orders, order_items)
- 다국어 지원

## 4. 로그인 및 권한 관리

### MVP
- Supabase Auth 이메일 로그인 필수
- 초기에는 관리자 계정 중심으로 운영
- RLS(Row Level Security)는 MVP에서 구현하지 않음

### 권한 단계 (2차 개발 구현 예정)

권한의 기본 단위는 **바이어**다. 영업/제안 업무는 담당 바이어 중심으로 운영되고, 브랜드/공급사는 상대적으로 변동이 잦다.

| 역할 | 권한 범위 |
|------|-----------|
| `admin` | 모든 바이어·브랜드·제품·견적·발송기록 열람 및 수정/삭제 가능 |
| `manager` | 지정된 바이어와 그 바이어 관련 견적·발송기록 열람 및 수정 가능 |
| `viewer` | 지정된 바이어 관련 정보만 열람 가능 |

### 확장 설계 포인트
- 모든 테이블의 `created_by` 컬럼 = `auth.users.id` (저장은 MVP부터, 활용은 2차)
- 향후 추가할 테이블:
  - `user_profiles` — 사용자 역할 및 기본 정보 저장 (`role`: admin / manager / viewer)
  - `buyer_access` — 사용자별 접근 허용 바이어 목록 (user_id + buyer_id 매핑)
- **MVP 인증 방식**: 현재 MVP는 클라이언트 사이드 세션 체크 방식으로 로그인 보호를 구현한다. 향후 SaaS화 또는 보안 강화 단계에서는 `@supabase/ssr` + `proxy.ts` 기반 서버사이드 라우트 보호로 전환할 수 있다.

## 5. 통화 및 견적 기준

- 기본 견적 통화: **USD**
- 지원 통화: `KRW`, `USD`, `EUR`, `기타`
- 제품별 공급가 통화와 견적별 견적 통화는 별도 관리
- 환율: MVP에서는 자동 연동 없음 — 수동 입력 또는 메모로 관리
- 과거 견적 보존: `proposal_items`에 견적 생성 당시 가격 스냅샷 저장 (공급가 변경과 무관하게 유지)

---

## 6. 마진 계산 방식

### MVP 기본 방식 — A. 공급가 기준 마크업

```
buyer_price = supply_price × (1 + margin_rate / 100)
```

예: 공급가 $10, 마진율 30% → 바이어 판매가 $13.00

### 2차 개발 옵션 — B. 판매가 기준 목표이익률

```
buyer_price = supply_price / (1 - margin_rate / 100)
```

예: 공급가 $10, 목표이익률 30% → 바이어 판매가 $14.29

> MVP에서는 A방식만 구현한다.

## 7. 거래조건 관리

포지클은 공급사로부터 EXW 또는 FOB 조건으로 공급가를 받고, 바이어에게는 다른 조건(예: FOB, CIF)으로 제안하는 경우가 있다. 이 경우 국내 물류비·운송비·포장비·핸들링비 등 부대비용이 발생하며, 실제 예상 마진율과 표시 마진율이 달라질 수 있다.

### MVP 방식
- `proposal_items`에 `supplier_incoterm`, `buyer_incoterm`, `cost_notes` 저장
- 비용 세부 항목은 테이블로 나누지 않고 메모 중심으로 관리

### 필드 정의

| 필드 | 설명 | 추천 값 |
|------|------|---------|
| `supplier_incoterm` | 공급사 기준 거래조건 | `EXW`, `FOB`, `CIF`, `DDP` |
| `buyer_incoterm` | 바이어 제안 기준 거래조건 | `EXW`, `FOB`, `CIF`, `DDP` |
| `cost_notes` | 물류비·운송비·부대비용 메모 | 자유 입력 |

### 2차 개발
- `proposal_cost_items` 테이블 추가: 국내 운송비, 국제 배송비, 포장비, 인증비, 샘플비 등 항목별 관리

## 8. 핵심 기능 정의

### 8-1. 브랜드/공급사 관리
- 브랜드명, 공급사명, 국가, 카테고리
- 담당자, 연락처
- 메모, 관련 자료 링크 (복수)

### 8-2. 제품 관리
- 소속 브랜드, 제품명, 카테고리, 효능/포지션
- 공급가, 통화 (KRW / USD / EUR 등)
- MOQ, 리드타임
- 인증 상태 (없음 / 진행중 / 완료) — CPNP, CPSR, FDA, TFDA 등 종류 포함
- 성분표 보유 여부, 인허가 자료 보유 여부
- 제품 이미지/자료 링크 (복수, 메타데이터 포함)
- 활성/비활성 상태

### 8-3. 바이어 관리
- **회사 단위로 관리** (MVP: 대표 담당자 1명만 저장)
- 회사명, 국가, 담당자, 연락 채널 (이메일, WhatsApp, Line, Alibaba)
- 관심 카테고리, 선호 가격대
- 채널 유형: 리테일 / 이커머스 / 라이브커머스 / 총판 / 클리닉 / 에스테틱 / 기타
- 메모
- 2차 개발: `buyer_contacts` 테이블로 담당자 다중 관리 확장

### 8-4. 견적 생성

> **단가 중심 설계**: 초기 제안 단계에서는 바이어의 발주 수량이 미확정인 경우가 많으므로, 단가(unit price)를 핵심값으로 두고 수량·총액은 선택값으로 처리한다.

- 바이어 선택 → 제품 복수 선택
- 제품별: 공급가 확인 → 마진율(%) 입력 → 바이어 단가 자동 계산 (A방식)
- 거래조건 입력 (supplier_incoterm, buyer_incoterm, cost_notes)
- 수량(quantity): **선택 입력** — 입력 시 총액 자동 계산
- 총액(total_price): **선택 표시** — 수량 입력 시에만 표시
- 통화 및 견적 메모 작성
- 저장 후 화면에서 확인 가능

### 8-5. 발송 기록
- 연결된 견적 또는 별도 발송
- 바이어, 브랜드/제품, 발송 채널, 발송일, 첨부 자료 종류, 메모 저장

### 8-6. 후속 연락 관리
- 발송 기록에 follow-up 예정일 및 상태 연결
- 상태: 예정 / 완료 / 보류 / 무응답 / 관심 있음 / 샘플 요청 / 견적 재요청
- 대시보드에서 오늘/이번 주 예정 목록 표시

### 8-7. 히스토리
- 바이어 상세 → 과거 발송 이력 전체 확인
- 브랜드/제품 상세 → 제안된 바이어 목록 확인

### 8-8. 대시보드
- 전체 바이어 수, 브랜드 수, 제품 수
- 이번 주 발송 건수
- 오늘 예정된 후속 연락 목록
- 최근 발송 기록 5건
- 관심 상태(관심 있음 / 샘플 요청) 바이어 목록

### 8-9. 자료 파일 관리

MVP에서는 실제 파일 업로드 없이 **Google Drive URL + 메타데이터 저장** 방식으로 관리한다.

#### 저장 메타데이터

| 필드 | 설명 | 추천 값 |
|------|------|---------|
| `file_type` | 자료 종류 | 브랜드소개서, 제품소개서, 가격표, 성분표, 인증자료, 수권서, 상표, 디자인자료, 패키지/칼선, 기타 |
| `file_stage` | 파일 단계 | `supplier_original`, `internal_working`, `buyer_sent`, `final` |
| `language` | 언어 | `KR`, `EN`, `TC`, `CN`, `JP`, `기타` |
| `version_label` | 버전 | `v1`, `v2`, `2026-04` 등 자유 입력 |
| `is_current` | 최신본 여부 | true / false |
| `source` | 출처 | `supplier`, `posicle`, `buyer`, `agency`, `other` |
| `file_url` | Google Drive 링크 | — |
| `notes` | 메모 | — |

#### 파일명 추천 규칙

```
[브랜드명]_[자료종류]_[언어]_[단계]_[버전]_[날짜]
```

예시:
```
ANGELS_LIQUID_BrandDeck_EN_supplier_original_v1_20260427
ONCLO_PriceList_USD_internal_working_v2_20260427
HEALIC_IngredientList_TC_buyer_sent_v1_20260427
```

> 2차 개발에서 Google Drive API 연동 시 파일명 자동 추천 기능으로 확장한다.

## 9. 주요 사용 시나리오

| 시나리오 | 핵심 흐름 |
|----------|-----------|
| 대만 바이어 — 미백 앰플 요청 | 제품 검색 → 견적 구성 → 저장 → 발송 기록 → follow-up 일정 생성 |
| 말레이시아 라이브커머스 — 저가 대량 | 가격/MOQ/채널 필터 → 견적(단가+거래조건) → WhatsApp 발송 기록 |
| 유럽 바이어 — CPNP 완료 제품만 | 인증 상태 필터 → 자료 보유 여부 확인 → 발송 기록 |
| 중복 제안 방지 | 바이어 상세에서 과거 발송 이력 즉시 확인 |
| 공급가 변경 | 제품 공급가 수정 + 메모로 변경 이유 기록 |
| EXW→FOB 마진 조정 | 거래조건 + cost_notes에 부대비용 메모 후 마진율 조정 |
